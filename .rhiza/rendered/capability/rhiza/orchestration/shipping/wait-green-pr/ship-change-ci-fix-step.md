## statement

The built-in ship-change workflow sends a failure at pr-green or rebased-green (on.fail) to conflict-triage, which runs `rhiza ship check --conflicts` and falls back (its on.fail) to a command step ci-triage on anything but a merge conflict, so red CI reaches ci-triage through conflict-triage. ci-triage runs `rhiza ship check --test-failures`: it passes only when the head's latest ship check recorded at least one CI finding (a parsed test failure, or a recognised non-test cause such as a self-check, fmt-check, vet or compile, or make-target failure; see ship-check-ci-cause-findings), and fails otherwise; ci-triage's on.fail goes to the wait step wait-ci-rerun, so an infra-only failure, or one with neither a failing test nor a recognised cause, waits for CI to move past the red head and then re-checks at pr-green instead of ending the run. ci-triage passes to ci-fix, an agent step (kind = "agent", one fixer session on the run worktree) whose prompt is the review fixer's prompt told to read the CI findings from `rhiza ship check --json` (its failing tests and recognised non-test causes, as no-leaf findings with the failing log lines), reproduce each locally with the repo's scoped command for it (the test command for a test, the matching check command for a lint, format, vet or self-check finding), and make one new commit with a Review: <run> trailer before `rhiza session done`; ci-fix passes to render-pr, then open-pr, wait-pr, pr-green and signoff. ci-fix runs at most twice per run (max_visits 2, so a third red head with CI findings goes over the cap and fails the run, pr-green's or rebased-green's output naming the failing tests); ci-triage has max_visits 3; render-pr, open-pr, wait-pr and pr-green have max_visits 10 and signoff max_visits 8, so two CI fixes, conflict fixes and the owner's two request-changes fit; rebase, wait-rebased and rebased-green have max_visits 6 so a run re-enters them after each CI or conflict fix routed from rebased-green. After land, a failure at landed-green, rebase-merge or rebased-merge-green goes to conflict-triage-landed, whose non-conflict failures go on through rebase-merge-gate-failed to landed-infra-triage: a red with no failing test waits in landed-infra-wait and returns to landed-green (ship-change-landed-infra-wait), while a red with a failing test or any other non-infra failure still ends the run there
