## statement

`rhiza guide planner` gives a planner afk's planner prompt in Rhiza's words on six sections in order (Task, Expected outcome, Read first, Must do, Must not do, Context), with the plan steps for a plan run and for planning with the owner in a chat, autonomous runs, a research pass before any Decision or leaf (the change set's slice and `rhiza why`, then the code and tests the intent touches, found by searching the names it uses, and the patterns a builder would follow; each leaf names the files it touches; a question only for what that reading cannot settle) and a self-check after writing (re-read `rhiza slice <change> --json`, check every intent clause served by a leaf, every leaf one concern with a runnable acceptance scoped to its tests, every Decision with provenance and no unreal depends-on, run `rhiza check`, and fix what it finds before session done), with the shared session-done, command-budget, never-list and outside-work blocks. The rest of today's plan topic moves into two plain reference topics the planner's Read first names, read with `rhiza guide` and not installed as skills: `rhiza guide plan-recipes` (scope by kind, the apply recipes, no plan file, who records a pick, Decisions and their provenance) and `rhiza guide plan-interview` (the interview with the owner, the Source it keeps, and milestone planning). Each of the three is a topic measured against TopicCap with its shared blocks expanded, so the split, not a cut of content, keeps them within it.
